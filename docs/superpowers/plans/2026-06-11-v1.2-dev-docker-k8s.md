# v1.2:开发全容器化 + K8s 生产部署计划 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development。

**Goal:** ① 开发模式一条命令 docker 起全栈(五服务,免装 node/pnpm);② 生产交付 K8s 部署物:`deploy/k8s/` 清单 + 部署计划文档。

### Task 2: K8s 生产部署物

**Files:** Create `deploy/k8s/`(清单)+ `deploy/k8s/README.md`(部署计划);Modify 根 README 链接。

- [ ] 清单(kustomize 风格平铺即可,不强求 overlay):
  - `namespace.yaml`(byok)
  - `secrets.example.yaml`(byok-secrets:DATABASE_URL/MASTER_KEY/SESSION_SECRET/REDIS_URL——模板含生成命令注释,**绝不含真值**;文档写明推荐 SealedSecrets/SOPS/外部 Secret 管理)
  - `migrate-job.yaml`(Job,worker 镜像跑 dist/migrate.js,ttlSecondsAfterFinished)
  - `gateway.yaml`(Deployment 3 副本 + Service;readiness/liveness=GET /healthz;resources requests/limits 给合理初值;preStop sleep 5 + terminationGracePeriodSeconds 30 对齐网关 25s 排水;env from secret)
  - `worker.yaml`(Deployment 1 副本——XREADGROUP 消费组天然支持多副本,文档说明扩容方式;无探针端口→liveness 用进程级或省略,注明)
  - `console.yaml`(Deployment 2 副本 + Service;readiness GET /login;env 含 GATEWAY_PUBLIC_URL)
  - `ingress.yaml`(两 host:api.<domain> → gateway、console.<domain> → console;注释标注按公司 ingress class/TLS 改)
  - PG/Redis:**不部署在集群内**,文档明确推荐用公司托管实例/云服务(理由:有状态服务运维),secrets 里只放连接串;附可选的 dev 用 StatefulSet 简版链接到 compose 方案。
- [ ] `deploy/k8s/README.md` 部署计划:前置(镜像推私有 registry:构建/打 tag 命令)、部署顺序(ns→secret→migrate Job 等待 Complete→三 Deployment→ingress)、升级流程(镜像 tag 滚动+migrate Job 先行)、回滚、扩缩容建议(gateway HPA 思路)、监控接入点(XLEN/XPENDING/DLQ + /healthz)、与 compose 方案的取舍。
- [ ] 验证:`kubectl apply --dry-run=client -f deploy/k8s/`(本机有 kubectl 则跑;没有则用 docker 跑 kubeconform 校验 schema;都不可用则 YAML 语法校验并在报告注明)。
